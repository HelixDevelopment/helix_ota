CONCLUSION (FACT, not guess): the failure is D1's NETWORK PATH to nezha, NOT the
helix control-plane server. nc to an unrelated, known-listening port (sshd:22)
also times out and on-link ICMP is 100% lost, which exonerates the OTA server.
Consistent with VPN full-tunnel capture (tun1) and/or Wi-Fi AP client-isolation
blocking wlan-client -> wired-LAN-host traffic. D2 (Ethernet) on the same server
reached every endpoint. Remediation (toggling VPN / Wi-Fi isolation) requires a
device state change, which is FORBIDDEN here (§11.4.122/§11.4.133); D1's
device-originated leg is therefore OPERATOR-BLOCKED (topology, §11.4.3), with the
server-side registration leg confirmed working.
